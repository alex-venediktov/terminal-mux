# terminal-mux: постановка и вывод о реализуемости

Документ отвечает на два вопроса: можно ли объединить несколько консольных приложений (Claude Code,
pi, PowerShell, cmd) в одном окне с полной эмуляцией их интерфейса и управления, и каким должно быть
такое приложение. Вывод подтверждён работающим прототипом - приложением этого репозитория, версия
0.1.0. Пользовательское описание (возможности, клавиши, конфиг, сборка) - [README](../README.md).

## 1. Вывод о реализуемости

**Совместное использование stdio невозможно; полноценное объединение возможно** - тем же способом,
каким устроены tmux, Zellij, WezTerm и Windows Terminal.

Почему не работает «общий stdio»:

- **каналы вместо консоли.** Claude Code, pi и PowerShell проверяют, подключены ли они к
  терминалу. На каналах (pipes) интерфейс не запускается: приложение уходит в неинтерактивный режим
  или теряет цвета, курсор и полноэкранный режим;
- **одна консоль на несколько процессов.** Все пишут в один экранный буфер и читают один поток
  ввода: вывод перемешивается, нажатия достаются случайному процессу;
- **перехват процесса из другого окна.** Консоль процесса, запущенного в Windows Terminal,
  принадлежит чужому хосту и на лету не забирается. `AttachConsole` с `ReadConsoleOutput` читает
  буфер только классического conhost и не годится для приложений, рисующих VT-последовательностями;
- **встраивание чужих окон** (`SetParent`) с Windows Terminal не работает: вкладки - не отдельные
  окна.

Что работает: **каждый дочерний процесс получает собственный псевдотерминал (ConPTY)**, его поток
VT-последовательностей разбирается эмулятором терминала в отдельную экранную сетку, хост рисует
сетку активного экземпляра и переводит клавиатуру и мышь обратно в VT-последовательности для
ввода этого экземпляра. Фоновые экземпляры продолжают работать, переключение - смена видимой сетки.

### Что подтверждено прототипом

| Критерий | Чем подтверждено |
|---|---|
| несколько экземпляров в своих ConPTY, переключение, вывод фоновых не теряется | работа человека в окне; тест `cmd_in_conpty_echoes_typed_command_output` (`src-tauri/src/pty.rs`) |
| интерфейс Claude Code отрисован полностью | сессия Claude Code, работавшая внутри terminal-mux (скриншот человека, 07.10.2026) |
| ввод: набор, Shift+Enter, вставка текста и картинки | проверено человеком 07.10.2026; вставка текста - «лучше, чем в Windows Terminal» |
| изменение размера окна передаётся процессу | проверено человеком; `resize` в том же тесте |
| pi запускается, работает, прокрутка истории есть | проверено человеком |
| проекты и сессии с диска, продолжение `--continue` | индекс проектов (`src-tauri/src/sessions.rs`, тесты); проверено человеком |
| SSH-подключения из `~/.ssh/config`, PowerShell от администратора | проверено человеком |

Отдельно не проверялись: Ctrl+C и Esc в каждом приложении, режимы мыши, ширина эмодзи и
иероглифов, работа на Windows 10.

## 2. Решение

**GUI-окно, а не TUI внутри терминала.** Хост в виде консольного приложения эмулировал бы терминал
внутри другого терминала: любое расхождение ширины символов между двумя эмуляторами сдвигает
разметку, часть сочетаний клавиш перехватывает внешний терминал, выделение мышью захватывает и
боковую панель. GUI-окно рисует терминалы само.

**Tauri 2 (Rust) + xterm.js 6.**

- Rust-ядро: ConPTY через `portable-pty`, запуск и завершение процессов, индекс проектов, конфиг,
  повышение прав, разбор `ssh_config`. Один исполняемый файл 4,6 МБ (замер 07.10.2026) плюс
  WebView2, входящий в Windows 11.
- xterm.js - эмулятор терминала VS Code: альтернативный экран, мышь, true color, bracketed paste,
  отрисовка через WebGL.

### Устройство

```
 окно (WebView2)                                       Rust (Tauri)
 ------------------------------                        ------------------------------
 xterm.js на каждый экземпляр  <-- событие pty-output -- поток чтения ConPTY экземпляра
 клавиши хоста, вставка        --- команда write ----->  очередь записи экземпляра -> ConPTY
 панель проектов, команды      --- spawn / kill ------>  процесс в своём псевдотерминале
                               <-- событие pty-exit ---- опрос завершения процесса
```

| Файл | Ответственность |
|---|---|
| `src-tauri/src/pty.rs` | экземпляры: ConPTY, чтение вывода, запись, размер, завершение; очистка окружения |
| `src-tauri/src/sessions.rs` | проекты из хранилищ сессий Claude Code и pi |
| `src-tauri/src/config.rs` | конфиг: место, умолчания, слияние, частичное обновление |
| `src-tauri/src/elevate.rs` | запуск с повышением прав через UAC |
| `src-tauri/src/ssh.rs` | хосты из `~/.ssh/config` |
| `src/main.ts` | окно: терминалы, панель, клавиши, вставка |

### Неочевидные требования к хосту

Каждое из них в прототипе выявлено на практике; без него хост ломается так, как описано.

1. **Ответ на запрос позиции курсора.** ConPTY (`portable-pty` создаёт его с признаком наследования
   курсора) первым делом шлёт `ESC[6n` и не отдаёт вывод, пока хост не ответит. xterm.js отвечает
   сам; хост без эмулятора, например тест, обязан ответить `ESC[1;1R`.
2. **Неполный символ UTF-8 на границе порций** переносится в следующую порцию, иначе кириллица и
   рамки ломаются на стыках.
3. **Окружение родительской сессии Claude Code не передаётся дочерним процессам.** Хост,
   запущенный из Claude Code, наследует `CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`,
   `CLAUDE_CODE_SESSION_ID` и другие переменные; дочерний claude тогда считает себя вложенной
   сессией и пишет «Transcript saving is off». Список - `SESSION_ENV` в `pty.rs`.
4. **Shift+Enter кодирует хост.** ConPTY передаёт модификаторы Enter только через win32-input-mode,
   которого xterm.js не поддерживает. Последовательность задаётся командой: `ESC CR` для Claude Code,
   `CSI 13;2u` для pi.
5. **Картинка из буфера** вставляется сочетанием приложения, а не данными: claude и pi в Windows
   читают буфер сами по Alt+V. Хост, увидев в буфере картинку без текста, отправляет это сочетание.
6. **Записи в экземпляр строго упорядочены**, а запись одного экземпляра не блокирует остальные:
   своя блокировка записи на экземпляр, команды вне главного потока, очередь записей во фронтенде.
7. **Корень проекта - по имени каталога хранилища, а не по `cwd` сессии.** Поле `cwd` в журнале
   Claude Code - текущий каталог оболочки, оно меняется при `cd` и устаревает при переименовании
   папки. Имя каталога хранилища кодирует корень, но неоднозначно (любой небуквенный символ
   становится `-`), поэтому путь восстанавливается сверкой с реальными каталогами диска.
8. **npm-обёртки `.cmd` запускаются через `node` напрямую.** Через `cmd /c` Ctrl+C вызывает вопрос
   «Terminate batch job (Y/N)?».

## 3. Требования (версия 0.1.0)

Функциональные требования реализованы и описаны в README: панель проектов, открытие с
продолжением сессии, набор команд в конфиге, SSH, повышение прав, клавиши, вставка, запоминание
окна. Здесь - то, что задаёт их рамку.

- **Подключение к сессии - это запуск с продолжением, а не перехват.** Мультиплексор управляет
  только процессами, которые запустил сам; прошлые сессии открываются `--continue` (Claude Code, pi).
- **Учитываются только приложения с историей сессий** (поле `history` команды); оболочки и SSH
  открываются, но в панели проектов не отражаются.
- **Хранилища сессий только читаются.** Формат журналов Claude Code и pi внутренний и меняется между
  версиями; индекс берёт из них путь проекта и время изменения, ничего не записывая.
- **Платформа:** Windows 10 1809 и новее (ConPTY), проверено на Windows 11 сборки 26200; WebView2.
- **Конфиг и состояние окна** - рядом с исполняемым файлом (портативный режим), иначе в
  `~/.terminal-mux/`.

## 4. Риски и ограничения

| Риск | Последствие | Что делать |
|---|---|---|
| Потомки процесса, отвязанные от консоли, переживают закрытие экземпляра | висящие процессы (серверы MCP и т. п.) | запускать экземпляр в Job Object с завершением дерева при закрытии |
| Список переменных сессии Claude Code неполон для будущих версий | дочерний claude снова не сохраняет транскрипт | сверять `SESSION_ENV` с окружением новой версии; рассмотреть снятие всех `CLAUDE_CODE_*`, кроме пользовательских настроек |
| Открытие проекта, сессия которого жива в другом окне | два процесса продолжают один журнал | показывать живые сессии (`claude agents --json`, реестр `~/.claude/sessions/<pid>.json`) и предупреждать |
| Встроенный в Windows conhost отстаёт от Windows Terminal | артефакты отрисовки на старых сборках | поставлять свои `conpty.dll` и `OpenConsole.exe` (пакет `Microsoft.Windows.Console.ConPTY`) |
| Полноэкранные режимы приложений (`"tui": "fullscreen"` у Claude Code, `--tui-mode fullscreen` у pi) | у терминала нет истории, полоса прокрутки пуста | свойство приложений; прокрутка - их средствами |
| Процесс с повышенными правами не встраивается в окно | администраторская оболочка - отдельным окном | встраивание требует посредника с повышенными правами (как у `sudo` Windows 11 в режиме «Встроенный») и ослабляет границу UAC |
| Команды Tauri принимают программу и путь от фронтенда | при загрузке в окно чужого содержимого - запуск произвольных программ | окно показывает только встроенный интерфейс; не открывать в нём внешние адреса, задать CSP |

## 5. Отвергнутые варианты

| Вариант | Причина отказа |
|---|---|
| общий stdio, одна консоль на всех, перехват чужой консоли, `SetParent` | раздел 1 |
| TUI-хост внутри терминала | двойная эмуляция: расхождение ширины символов, перехват клавиш внешним терминалом, выделение вместе с панелью |
| Rust GUI без веб-слоя (egui или iced + `alacritty_terminal`) | собственная отрисовка шрифтов, выделения и клавиатуры - объём несоизмерим с выигрышем |
| Go (`charmbracelet/x/vt`), .NET (XtermSharp) | эмуляторы терминала незрелые: до версии 1.0 и пререлиз |
| Node + Ink в роли хоста | тот же эмулятор xterm.js, но свой интерфейс на Ink мерцает под ConPTY |
| встроенный `sudo` и свой посредник для повышения прав | `sudo` по умолчанию выключен; посредник ослабляет UAC; выбрано отдельное окно с диалогом UAC |
| вложенные проекты как часть родительского | `D:\projects\Pi` и `D:\projects\Pi\3d` - разные проекты со своими сессиями |

## 6. Дальнейшие шаги

1. Job Object для экземпляров: завершение всего дерева процессов при закрытии.
2. Статус живых сессий в панели (занят, ждёт ввода) - `claude agents --json`, hooks Claude Code,
   режим `--mode rpc` у pi; предупреждение о второй копии сессии.
3. Свои `conpty.dll` и `OpenConsole.exe` в поставке; проверка на Windows 10.
4. Подпись исполняемого файла и установщиков, иконка приложения.
5. Автотесты интерфейса: переключение, закрытие, вставка, клавиши.

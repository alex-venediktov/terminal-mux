# terminal-mux

Мультиплексор консольных приложений для Windows: Claude Code, pi, PowerShell и cmd в одном окне.
Каждое приложение работает в собственном псевдотерминале (ConPTY) и отображается полноценным
эмулятором терминала, поэтому интерфейс, цвета, мышь и клавиатура ведут себя так же, как в
Windows Terminal.

## Возможности

- **Панель проектов слева.** Проекты собираются из хранилищ сессий Claude Code
  (`~\.claude\projects`) и pi (`~\.pi\agent\sessions`), включая каталоги без сохранённых сессий.
  Проекты, чьи рабочие каталоги удалены с диска, не показываются. Сортировка по дате последней
  активности или по имени; дата - «сегодня ЧЧ:ММ» либо `ДД.ММ.ГГГГ`. Тип проекта - иконки
  приложений, чья история в нём есть (claude, pi), свежая первой.
- **Открытие проекта двойным кликом.** Если в проекте уже запущен экземпляр, он становится
  активным; иначе запускается приложение, которым в проекте пользовались последним, с
  `--continue`. Проект без истории открывается новой сессией Claude Code.
- **Несколько экземпляров одновременно.** Фоновые экземпляры продолжают работать, их вывод не
  теряется. Имя активного экземпляра и проекта - в заголовке окна. Проект с живым claude или pi
  отмечен точкой.
- **Новый сеанс в любом каталоге.** Кнопка «каталог...» открывает системный диалог выбора папки
  (с созданием новой) и запускает в ней сеанс.
- **Набор команд задаётся в конфиге**: программа, аргументы, иконка, последовательность для
  Shift+Enter. По умолчанию - Claude Code, pi, Windows PowerShell, PowerShell от администратора
  и cmd. Команда с `elevate` запрашивает повышение прав диалогом UAC и открывается в отдельном
  окне, как из Проводника.
- **SSH-подключения** из `~\.ssh\config`: кнопка `ssh` открывает список хостов (записи `Host`
  без шаблонов, с `User@HostName:Port` в подписи), выбор открывает экземпляр `ssh <хост>`; имя
  хоста - в заголовке окна. SSH-сеансы, как и оболочки, в панели проектов не учитываются.
- Процесс, завершившийся с кодом 0 (например, по `exit`), закрывается; при другом коде экземпляр
  остаётся с сообщением о завершении.

## Клавиши

| Клавиши | Действие |
|---|---|
| Ctrl+PgUp / Ctrl+PgDn | предыдущий / следующий экземпляр |
| Alt+= / Alt+- / Alt+0 | крупнее / мельче / исходный размер шрифта |
| Alt + колесо мыши | размер шрифта |
| Ctrl+C при выделенном тексте | копировать (без выделения - передаётся приложению) |
| Ctrl+V | вставить текст (с bracketed paste, если приложение его включило); картинку - сочетанием из `pasteImage` |
| Shift+Enter | последовательность из поля `shiftEnter` команды |

Размер шрифта и порядок сортировки сохраняются в конфиг.

## Требования

- Windows 10 1809 или новее (ConPTY); проверено на Windows 11 26200.
- WebView2 Runtime - входит в Windows 11, для Windows 10 ставится установщиком.
- Сами запускаемые приложения в `PATH`: `claude`, `pi` и т. д.

Для сборки дополнительно: Rust (MSVC-тулчейн, Visual Studio Build Tools), Node.js.

## Сборка и запуск

```
npm install
npm run tauri dev          # запуск для разработки
npm run tauri build        # exe и установщики
```

Результат `npm run tauri build`:

| Файл | Размер (замер 07.10.2026) |
|---|---|
| `src-tauri/target/release/terminal-mux.exe` | 4,6 МБ |
| `src-tauri/target/release/bundle/msi/terminal-mux_0.1.0_x64_en-US.msi` | 2,2 МБ |
| `src-tauri/target/release/bundle/nsis/terminal-mux_0.1.0_x64-setup.exe` | 1,5 МБ |

`terminal-mux.exe` самодостаточен: интерфейс встроен в исполняемый файл.

Проверки:

```
npx tsc --noEmit
cargo test --manifest-path src-tauri/Cargo.toml
```

После переноса каталога проекта кеш `src-tauri/target` хранит прежние абсолютные пути, и
сборка падает на чтении разрешений Tauri; лечится `cargo clean --manifest-path src-tauri/Cargo.toml`.

## Конфиг

Файл `config.json` ищется в двух местах:

1. рядом с `terminal-mux.exe` - портативный режим;
2. `~\.terminal-mux\config.json` - иначе; создаётся с настройками по умолчанию при первом запуске.

```json
{
  "fontSize": 14,
  "sort": "date",
  "commands": [
    {
      "id": "claude",
      "title": "Claude Code",
      "icon": "✳",
      "color": "#d97757",
      "program": "claude",
      "args": [],
      "continueArgs": ["--continue"],
      "history": "claude",
      "shiftEnter": "\u001b\r"
    }
  ]
}
```

| Поле команды | Смысл |
|---|---|
| `id`, `title` | идентификатор и подпись (в подсказке и заголовке окна) |
| `icon` | символ или путь к `.png`, `.svg`, `.ico`, `.jpg` |
| `color` | цвет символьной иконки |
| `program`, `args` | что запускать; имя ищется в `PATH`, переменные вида `%SystemRoot%` раскрываются, npm-обёртка `.cmd` запускается через `node` напрямую; `{cwd}` в аргументах заменяется каталогом проекта (без проекта - домашним) |
| `continueArgs` | аргументы продолжения последней сессии; добавляются, если в проекте есть история этой команды |
| `history` | хранилище сессий команды: `claude` или `pi`. Команды без него не учитываются в панели проектов |
| `shiftEnter` | что отправить приложению по Shift+Enter |
| `elevate` | `true` - запуск с повышением прав (UAC) в отдельном окне вне мультиплексора |
| `pick` | `ssh-hosts` - перед запуском выбрать хост из `~\.ssh\config`; он подставляется вместо `{host}` в аргументах |
| `pasteImage` | что отправить приложению, когда в буфере картинка без текста; claude и pi в Windows вставляют картинку по Alt+V (`v`) и читают буфер сами |

Список `commands` из файла заменяет список по умолчанию целиком; отсутствующие в файле
ключи верхнего уровня берутся из умолчаний.

## Как это устроено

```
 xterm.js (эмуляция и отрисовка) <-- события pty-output --  Rust: ConPTY (portable-pty)
 панель проектов, клавиши        --  команда write      -->      процесс claude / pi / ...
```

- `src-tauri/src/pty.rs` - экземпляры: псевдотерминал, чтение вывода (неполный символ UTF-8
  переносится в следующую порцию), запись ввода, изменение размера, завершение.
- `src-tauri/src/sessions.rs` - индекс проектов из хранилищ claude и pi.
- `src-tauri/src/config.rs` - конфиг: место, умолчания, слияние.
- `src-tauri/src/ssh.rs` - хосты из `~\.ssh\config`.
- `src-tauri/src/elevate.rs` - запуск с повышением прав (ShellExecute `runas`), подстановка `{cwd}`.
- `src-tauri/src/lib.rs` - команды Tauri и события.
- `src/main.ts` - окно: терминалы, панель, клавиши, конфиг.

## Ограничения

- **Подключиться к сессии, запущенной в другом окне, нельзя**: консоль чужого процесса не
  перехватывается. Открытие такого проекта запускает второй процесс, который продолжит тот же
  журнал сессии параллельно с первым.
- **Shift+Enter.** xterm.js не поддерживает win32-input-mode ConPTY, поэтому сочетание
  кодирует мультиплексор: Claude Code получает `ESC CR`, pi - `CSI 13;2u`. Если приложение
  ждёт другого, поле `shiftEnter` меняется в конфиге.
- **Процесс с повышенными правами не встраивается в окно**: подключить его к псевдоконсоли
  обычного процесса Windows не позволяет. Команды с `elevate` открываются в отдельном окне;
  встраивание потребовало бы посредника с повышенными правами, как у `sudo` Windows 11 в режиме
  «Встроенный».
- **Переменные окружения сессии Claude Code** (`CLAUDECODE`, `CLAUDE_CODE_CHILD_SESSION`,
  `CLAUDE_CODE_SESSION_ID` и др.) не передаются дочерним процессам: без этого claude, запущенный
  из мультиплексора, который сам запущен из Claude Code, считает себя вложенной сессией и не
  сохраняет транскрипт. Список переменных - `SESSION_ENV` в `src-tauri/src/pty.rs`; новые версии
  Claude Code могут добавить свои.
- **Пути проектов без сессий** восстанавливаются из имён каталогов хранилищ сверкой с диском:
  кодирование хранилищ заменяет любой небуквенный символ на `-`, поэтому без существующего
  каталога путь не восстановить.
- **Полоса прокрутки** есть только у приложений, которые пишут в обычную историю терминала
  (cmd, PowerShell). Claude Code с настройкой `"tui": "fullscreen"` и pi в режиме по умолчанию
  (`--tui-mode fullscreen`) работают на альтернативном экране: у терминала нет истории, прокрутку
  ведёт само приложение колесом мыши и PgUp/PgDn. Обычную историю с полосой дают `"tui"` по
  умолчанию у Claude Code и `--tui-mode regular` у pi.
